# Планировщик задач для команды — мини-приложение MAX

Мини-приложение (Mini App) для мессенджера **MAX** + Telegram-подобный бот для
уведомлений. Администратор раздаёт задачи, сотрудники работают с ними внутри MAX,
уведомления приходят через бота.

- **Frontend:** React + TypeScript + Vite (дизайн в стиле «liquid glass», русский UI)
- **Backend:** Node.js + TypeScript + Express
- **БД:** PostgreSQL (чистый SQL + миграции, без ORM)
- **Авторизация:** проверка подлинности MAX `initData` на backend (HMAC-SHA256)
- **Запуск:** Docker Compose

> ⚠️ **Безопасность.** Токен бота, секреты и доступ к БД хранятся только в `.env`
> на backend и **никогда** не попадают во frontend. Файл `.env` добавлен в
> `.gitignore`. Роль пользователя (ADMIN/USER) определяется только на сервере по
> `ADMIN_MAX_USER_ID` — её нельзя изменить из интерфейса или запросом к API.

## Что нужно от вас (заполнить в `.env`)

| Переменная           | Что это и где взять                                                        |
|----------------------|---------------------------------------------------------------------------|
| `MAX_BOT_TOKEN`      | Токен бота MAX. Получается при создании бота (см. шаг 1 ниже).             |
| `ADMIN_MAX_USER_ID`  | Ваш MAX user ID — этот аккаунт станет администратором.                     |
| `MAX_BOT_USERNAME`   | Юзернейм бота без `@` (для кнопки «Открыть приложение»).                   |
| `MINI_APP_URL`       | Публичный HTTPS-URL мини-приложения (после деплоя).                        |
| `POSTGRES_PASSWORD`  | Придумайте пароль для БД.                                                  |
| `APP_TIMEZONE`       | Часовой пояс, напр. `Europe/Moscow`.                                       |

Остальные переменные имеют разумные значения по умолчанию (см. `env.example`).

# Пошаговая инструкция

## 1. Что создать в MAX

1. Откройте в MAX чат с ботом-создателем ботов (**@MasterBot**).
2. Создайте нового бота и задайте ему имя и юзернейм.
3. В ответ вы получите **токен бота** — длинная строка. Это `MAX_BOT_TOKEN`.
4. Там же, в настройках бота, включите режим **Mini App (веб-приложение)** и
   укажите URL вашего приложения (пока можно временный; итоговый — после деплоя,
   см. шаг 6–7).

> Важно: по актуальным правилам MAX публикация ботов/мини-приложений может
> требовать верифицированного юрлица РФ. Для разработки и тестирования это не
> нужно — бот и Mini App работают сразу после создания.

## 2. Где взять ключи

- **`MAX_BOT_TOKEN`** — выдаётся @MasterBot при создании бота (раздел «Чат-боты»).
- **`ADMIN_MAX_USER_ID`** — ваш числовой MAX ID. Два способа узнать:
  - запустите проект, напишите боту `/start` — он ответит и пришлёт ваш ID
    (работает при `BOT_UPDATES_MODE=polling`);
  - или откройте Mini App — на экране входа показывается ваш ID.
- **`MAX_BOT_USERNAME`** — юзернейм, который вы задали боту (без `@`).

## 3. Какие значения вставить в `.env`

```bash
cp env.example .env
```

Откройте `.env` и заполните минимум:

```dotenv
POSTGRES_PASSWORD=придумайте_пароль
DATABASE_URL=postgres://taskuser:придумайте_пароль@db:5432/taskdb

MAX_BOT_TOKEN=вставьте_токен_от_@MasterBot
MAX_BOT_USERNAME=имя_вашего_бота_без_@
ADMIN_MAX_USER_ID=ваш_MAX_ID

APP_TIMEZONE=Europe/Moscow
# MINI_APP_URL=https://ваш-домен   # заполните после деплоя (шаг 6)
```

> Пароль в `POSTGRES_PASSWORD` и в `DATABASE_URL` должен совпадать.

## 4. Как запустить проект (локально)

Нужен установленный **Docker Desktop**.

```bash
docker compose up --build
```

Поднимутся три контейнера:

- `db` — PostgreSQL (порт 5432);
- `backend` — API + бот + планировщик (порт 3001 для отладки). Миграции
  применяются автоматически при старте;
- `frontend` — nginx с собранным мини-приложением на **http://localhost:8080**.

Проверка, что backend жив:

```bash
curl http://localhost:3001/api/health
```

### Запуск без Docker (альтернатива)

```bash
# backend
cd backend && npm install && npm run migrate && npm run dev
# frontend (в другом терминале)
cd frontend && npm install && npm run dev   # http://localhost:5173
```

Для backend без Docker в `.env` используйте `DATABASE_URL` с хостом `localhost`.

## 5. Как проверить Mini App

**Вариант А. Внутри MAX (как у реального пользователя).**
MAX загружает Mini App только по HTTPS с публичного адреса. Для локального теста
поднимите туннель (например, `cloudflared tunnel --url http://localhost:8080` или
`ngrok http 8080`), получите HTTPS-URL и укажите его в настройках бота как URL
веб-приложения. Затем откройте бота в MAX и запустите приложение.

**Вариант Б. Локально в браузере (для разработки интерфейса).**
Вне MAX нет `initData`, поэтому backend отклонит запросы. Сгенерируйте валидный
`initData` вашим токеном и подложите его фронту:

```bash
cd backend
npm run make-initdata -- --id ВАШ_ADMIN_MAX_ID --first Админ --username admin
```

Скопируйте выведенную строку в `frontend/.env.local`:

```dotenv
VITE_DEV_INIT_DATA=<строка из команды выше>
```

Запустите `cd frontend && npm run dev` и откройте http://localhost:5173 — вы
войдёте как администратор (подпись настоящая, проверка на backend включена).
Чтобы проверить роль обычного пользователя — сгенерируйте `initData` с другим
`--id`.

## 6. Как разместить на сервере

1. Залейте проект на сервер (git clone / scp).
2. Создайте `.env` с боевыми значениями (`NODE_ENV=production`, реальный
   `POSTGRES_PASSWORD`, `MINI_APP_URL=https://ваш-домен`).
3. Поднимите за HTTPS-прокси (обязательно HTTPS — требование MAX). Варианты:
   - поставить перед `frontend` reverse-proxy с TLS (Caddy / Traefik / nginx +
     Let's Encrypt);
   - или примонтировать сертификаты в отдельный nginx.
4. Запустите:
   ```bash
   docker compose up -d --build
   ```
5. Проверьте, что `https://ваш-домен` открывает приложение, а
   `https://ваш-домен/api/health` отвечает `{"ok":true}`.

## 7. Какой URL указать в MAX

В настройках бота (@MasterBot → ваш бот → Mini App) укажите публичный HTTPS-адрес
приложения, например `https://ваш-домен`. Этот же адрес пропишите в `.env` как
`MINI_APP_URL` — он используется в кнопке «Открыть приложение» в уведомлениях.

## 8. Как проверить уведомления бота

1. Убедитесь, что `BOT_UPDATES_MODE=polling` (по умолчанию) и backend запущен.
2. Напишите боту `/start` — придёт приветствие с вашим MAX ID (так вы
   зарегистрируетесь как пользователь).
3. Пусть сотрудник тоже напишет боту `/start` или откроет Mini App — он появится
   в разделе **Люди**.
4. Создайте задачу на этого сотрудника (кнопка **+ Новая задача**). Ему придёт
   сообщение от бота: «📋 Новая задача …» с кнопкой «Открыть приложение».
5. Сотрудник переводит задачу в «Выполнено» — вам (администратору) приходит
   «✅ Задача выполнена …».
6. Любой комментарий в задаче отправляет уведомление другой стороне.

> Если уведомления не приходят — проверьте логи backend
> (`docker compose logs -f backend`): при старте выводится проверка токена бота
> (`токен бота MAX валиден`).

## 9. Как проверить еженедельный отчёт

- По умолчанию отчёт уходит администратору **в понедельник в 09:00** в часовом
  поясе `APP_TIMEZONE`. Расписание меняется через `WEEKLY_REPORT_CRON`.
- Не дожидаясь понедельника, отчёт можно отправить вручную. Внутри контейнера
  backend запустите:
  ```bash
  docker compose exec backend node -e "require('./dist/scheduler/weeklyReport').runWeeklyReport().then(()=>process.exit(0))"
  ```
  Либо (без Docker, из папки `backend`):
  ```bash
  npx tsx -e "import('./src/scheduler/weeklyReport').then(m=>m.runWeeklyReport()).then(()=>process.exit(0))"
  ```
  Администратору придёт сообщение «📊 Еженедельный отчёт …».
- Ту же статистику можно смотреть в приложении: раздел **Отчёты** (текущая неделя,
  прошлая неделя, 30 дней).

## Роли и доступы (кратко)

- **ADMIN** (один, по `ADMIN_MAX_USER_ID`): главная со статистикой, все задачи с
  фильтрами и сортировкой, создание задач, список людей, отчёты, история задач,
  комментарии.
- **USER**: только свои задачи («Мои задачи», «Выполнено»), смена статуса своих
  задач (Начать → Выполнить), комментарии. Чужие задачи, статистику и управление
  не видит и не может получить через API (доступ проверяется на backend).

## Статусы и просрочка

`NOT_STARTED → IN_PROGRESS → DONE`. Отдельного статуса «просрочено» нет: задача
считается просроченной, если `deadline < now()` и статус ≠ `DONE`. В интерфейсе
такие задачи помечаются красным «Просрочено».

## API (вкратце)

Все маршруты, кроме `/api/health`, требуют заголовок `X-Max-Init-Data`.

| Метод | Путь                         | Доступ | Назначение                     |
|-------|------------------------------|--------|--------------------------------|
| GET   | `/api/health`                | —      | проверка живости               |
| GET   | `/api/auth/me`               | любой  | текущий пользователь и роль     |
| GET   | `/api/tasks`                 | любой  | свои задачи                     |
| GET   | `/api/tasks/:id`             | доступ | задача + комментарии (+история для админа) |
| PATCH | `/api/tasks/:id/status`      | исполнитель | смена статуса               |
| GET   | `/api/tasks/:id/comments`    | доступ | комментарии                     |
| POST  | `/api/tasks/:id/comments`    | доступ | добавить комментарий            |
| GET   | `/api/admin/stats`           | ADMIN  | статистика дашборда             |
| GET   | `/api/admin/tasks`           | ADMIN  | все задачи (filter/sort/order)  |
| POST  | `/api/admin/tasks`           | ADMIN  | создать задачу                  |
| GET   | `/api/admin/users`           | ADMIN  | пользователи со счётчиками       |
| GET   | `/api/admin/assignees`       | ADMIN  | список исполнителей для формы    |
| GET   | `/api/admin/reports?range=`  | ADMIN  | отчёт за период                 |
